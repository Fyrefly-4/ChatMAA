# 真实 MAA 原型：等待下一步指令

本阶段尚未启动，也没有真实 MAA 调用代码。用户要求：涉及真实 MAA、模拟器或游戏时必须停止并等待其下一步指令。当前替身原型完成后停在这里。

## 启动前需要共同确定的输入

| 输入 | 当前状态 |
|---|---|
| MaaCore、资源、Python 绑定版本及安装位置 | 待提供并核对 |
| 固定模拟器/设备、连接方式、区服 | 待提供；连接信息仅留本地 |
| 登录完成、1-7 可用、已有代理 | 待用户确认环境就绪 |
| 首轮执行次数 | 待用户明确；不根据 MVP 十次目标擅自执行十次 |
| 停止实验安排 | 待确定在何阶段停止及现场如何核对 |

收到启动指令与必要输入后，先按所选版本核对 API 和受限参数，再编写最小 CLI。真实实验必须保持不吃药、不碎石；观察实际成功次数，保留原始事件、时间与现场核对结果。

建议首轮证据表：

| 场景 | 实际参数 | 原始反馈及时间 | 现场观察 | 可支持的业务解释 | 结论 |
|---|---|---|---|---|---|
| 少量 1-7 执行 | 待填写 | 待采集 | 待核对 | 成功计数依据 | 未验证 |
| 正常停止 | 待填写 | 请求返回与后续反馈分开记录 | 自动化与游戏内战斗分开核对 | 停止确认依据 | 未验证 |
| 理智不足/失败 | 仅在约定且能自然复现时执行 | 待采集 | 是否自动再开一局 | 是否满足本轮结束规则 | 未验证 |

取得证据后才能确定替身协议如何映射真实 MAA，再开展一次保留相同 HTTP 边界的合并验证。不得直接把替身的环境核对、计数或停止语义复制为实机保证。完整方案见 [设计审阅](../../docs/design-review.md)。
