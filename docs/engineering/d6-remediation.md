## 行为与代码入口

| 场景 | 行为与实现 |
|---|---|
| 停止后 total 目标无法核算 | `BusinessService.waitingGuidance` 提供统一说明、关联旧任务及取消能力；浏览器会话和 Runtime 上下文共用。Web 无方案时也可取消当前修订。环境恢复不补齐历史成果，明确的独立新增目标仍重新展示、确认 |
| 模型生成预算耗尽 | `runtime/budget.ts` 集中校验预算；`handoff.ts` 从持久业务记录生成失败交接。保留 failed 原因，不发布残缺正文，不重发已登记工具。已创建方案和任务仍可查、可停 |
| 运行中确认量与目标混淆 | 任务标题标明目标，运行中标明已确认量和未结算批次；结束后仍是下界时保留“至少”，不计算精确剩余 |
| 扫描、停止与环境检查等待 | `ProgressTime` 只计算已记录时间的时长；任务首条执行证据、停止事件和检查起始时间分别使用。最后事实与成功同步分开显示，缺少历史起始时间时明确说明 |
| 正常结束被笼统称作停止 | `goals.ts` 同时核对停止、目标、精确量、未结算、异常与正常完成依据；`resultText` 同时供任务卡和系统结果消息使用。异常、用户停止、部分完成、未知分别表达 |

Adapter 新快照的 `normal_completed` 只在正常原因、任务链完成、自动化停止且无执行错误时为 true；仍不单独证明目标达成。旧快照没有该字段时，仅在已有 `device=ready` 和其他完整成果条件都满足时解释为正常成功。原始快照与旧消息不改写。库存依据失效时，不能显示补库存目标已完成。

业务结果通知沿用结果摘要指纹去重；页面对重复引用的同一方案、任务只展示一次卡片。查询及刷新不会登记新的执行授权。

## 模型预算配置

MVP Runtime 使用 `CHATMAA_MODEL_MAX_OUTPUT_TOKENS`，允许 1000–16000 的整数。当前默认 **12000，属于待真实模型验证的候选值**；可在现有根目录 `.env` 保存一次，例如 `CHATMAA_MODEL_MAX_OUTPUT_TOKENS=6000` 恢复原预算。统一启动入口沿用该文件，不需每次输入。legacy Agent 不使用此配置。

每步实际预算记录在 `model_started.maxOutputTokens`，用量在 `model_step.usage`。仍限制 8 步、12 次工具调用、60 秒轮次时间、48000 字符上下文，模型不自动重试。读状态不再重复返回本会话的全局占用快照；保留目标来源、当前任务、展示与已登记操作。

更高输出预算可能增加费用及等待，不能保证任何兼容端点或模型不再失败。真实代表对话未验证前，不将候选预算记作模型问题已通过。

## 2026-09-28 已知限制与当前交接

本轮整改按当前范围交接，D6 尚未标记完成。保留以下待处理项：

- 执行前环境识别有效期为 5 秒。识别完成后仍要创建、加载并连接正式执行实例；这些准备超过有效期时会报 `environment evidence expired before execution`，即使前置识别成功也拒绝开战。后续应检查准备与识别的时序，不能靠清除历史记录或取消有效期保护解决。
- 模型可能将运行期间的新目标解释为可以等待前一任务后自动开始；系统实际没有自动队列。环境未释放时不能启动，恢复后仍需用户明确确认。
- 正式执行开始前的资源加载、连接与检查目前缺少更细的阶段反馈，受理至开始期间可能长时间只显示等待。
- 新结果分类可能在首次读取旧库时为历史任务补充新的结果摘要，原消息保留。相同事实的后续同步按指纹去重，但这不等同于升级时完全没有新增历史通知。
