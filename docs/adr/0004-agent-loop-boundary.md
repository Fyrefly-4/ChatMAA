# 首版复用 AI SDK 工具循环，长任务由 ChatMAA 管理

定位：持久架构决定；状态沿用 `accepted`，不代表已完整实现。元信息核对：2026-09-18。确认依据：[架构讨论 Q1–Q12](../archive/2026-09-prototype/architecture-discussion.md)；独立确认日期尚未逐项核实，不以本次整理日期代填。正文中的待验证状态按原讨论时间理解，后续验证见有日期的补充及[当前工程说明](../engineering/architecture.md)。

产品负责人选择 Q11=A：首版复用 AI SDK 的有界模型与工具调用循环，ChatMAA 保留上下文规则、授权检查、任务状态、设备占用、持久化、停止和恢复的责任。工具通过自有任务管理提交、查询或请求停止，MAA 长任务不依赖模型循环持续存活。

相较于现在自行编写循环，此选择减少通用编排工作，同时需要适配 SDK 的消息与工具接口。模型循环的步数上限不等于游戏执行超时，SDK 的结束或取消也不能代替执行端停止。

此决定不排除以后自写 Agent Loop，届时可以继续使用 SDK 的模型调用能力；任务管理与 MAA 接口应保持独立。具体隔离方式见 [当前工程说明](../engineering/architecture.md)，需要在实现与替换试验中验证；不承诺更换循环无须调整会话格式、工具关联或错误处理。

2026-09-20 规格迁移补充：当前产品行为与验收依据为 [MVP Spec #18](https://github.com/Fyrefly-4/ChatMAA/issues/18)，工程路线见 [#19](https://github.com/Fyrefly-4/ChatMAA/issues/19)。旧 #1 已被替代，正文中的旧规格引用保留历史语境；本 ADR 的职责、运行与记录边界继续适用。本次仅更新规格入口，没有新增实现或验证证据。
